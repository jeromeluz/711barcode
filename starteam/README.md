# 造勢物品管理系統｜歷史紀錄分頁版

適用 GitHub Pages + Firebase Realtime Database，保留免登入及原本的門市、人員、取用、歸還、盤點功能。

## 本次調整
- 「取用與歸還紀錄」、「盤點紀錄」分開顯示，各自依日期分組，日期與明細預設收合。
- 每區初次最多顯示 **10 筆操作**；同次取用多項物品、同次盤點全部物品均算一筆。
- 超過 10 筆時，底下「查看更多」每按一次追加 10 筆，並保留已展開的日期及明細。
- 盤點庫存僅修改 `expected`（門市應有總數量），**不修改** `remaining`（目前剩餘數量）；保留盤點前後的應有數量紀錄。

## 更新方式
將 `app.js` 和 `index.html` 覆蓋 GitHub 儲存庫的 `starteam/` 資料夾。**不要匯入或覆蓋 `initial-database.json`**，避免重設現有資料。若 GitHub Pages 快取未更新，請強制重新整理。

## 注意
Firebase 免登入公開讀寫可能被任何人修改資料，建議定期備份。


## 盤點 undefined 修正
修正原本應有數量未設定時，盤點紀錄 `before` 為 undefined 導致 Firebase transaction 失敗的問題。現在會以 `null` 記錄「未設定」，盤點只更新 expected，不修改 remaining。只需覆蓋 `app.js`，無須重匯資料庫。


## 新增門市
門市編輯中可輸入新門市名稱，按「新增門市」。每項物品的應有與剩餘數量初始均為 0。接著使用盤點庫存設定該門市應有總數量（盤點不改剩餘數量）。新增採用 Firebase transaction 避免同名及並行覆寫。
