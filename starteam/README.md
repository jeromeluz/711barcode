# 造勢物品管理系統（GitHub Pages + Firebase）

本版新增「良品／損壞品」管理。

- 應有總數 = 良品 + 損壞品。這是門市擁有的總數，與剩餘數量不同。
- 盤點庫存可一次修改全部物品的應有總數、良品數、損壞品數，並保留盤點紀錄。
- 盤點不會修改剩餘數量。
- 可借用 = min(剩餘數量, 良品數量)，不可超過可借用數量取用。
- 歸還仍會增加剩餘數量；超出應有總數會二次確認，並提醒盤點。
- 舊資料若沒有 good/bad 欄位，畫面暫時視為全部良品、損壞品 0，第一次盤點後會正式儲存好壞數量。
- 好壞數量代表該門市「應有道具總數」的狀態分類，並非即時追蹤每一件借出物品的好壞；取用/歸還不會自動改動好壞數量。

## 部署

將 `index.html`、`app.js` 上傳覆蓋到 GitHub Repository 的 `starteam/` 資料夾即可。保留原本 Firebase 資料，不要重新匯入 initial-database.json。若是首次部署，請依照既有 Firebase 設定與規則設定。

Firebase Realtime Database 必須允許寫入 inventory 節點。此版本維持免登入公開讀寫，請定期備份。
